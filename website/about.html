Why communist

We mean it literally. This is what it means for the code and for the people who use it.

No owners

No company, foundation or founder owns systemLinux. There's no trademark to license and no copyright assignment to sign. The copy you download is as much yours as anyone's.

No profit

No ads, no telemetry, no accounts, no premium tier. Big Tech makes its money turning your attention into someone else's profit. We don't sell anything, so there's nothing to sell you.

From each according to ability, to each according to need

Everyone gets the whole system, whether they contribute or not. Write code, test it on your hardware, translate, fix the docs, or just tell us what broke. Donations help, and they buy nothing: no say over the roadmap, no special treatment.

Decided in public

Decisions happen in the open repository, in issues and pull requests anyone can read and argue with. The people doing the work make the calls, and they answer to the people using it.

Against enclosure

Free software is a commons, and corporations keep fencing it off: open-core licences, cloud lock-in, "community editions" with the useful parts cut out. We build on the commons and give everything back to it. Nothing here will ever go behind a paywall.

Old hardware counts

A system that needs a new laptop is a system for people with money. systemLinux runs in about 3 GB of RAM, on machines companies have already written off. It only speaks English so far, and we need translators to change that.

What you get

A minimal console system. The live ISO is installer media only: kernel plus the bare minimum to install.

Minimal live ISO

The live image is only the kernel and what the installer needs: systemd, NetworkManager, disk and boot tools. No desktop, daemons, firmware bundles, docs or locale packs.

Install it yourself

The handbook lists every command. If you'd rather not type them, systemlinux-install runs the same steps. Use a whole disk, or a partition you've already freed up. It boots from a USB stick or Ventoy, in UEFI mode.

Build what you need

get URL downloads a source tarball, builds it and installs it where you say. It is a short POSIX shell script you can read in a minute.

Plain systemd

Services are ordinary systemd units. systemctl, journalctl and loginctl do what you already know they do.

Drivers built in

One kernel with Intel, AMD and open-source NVIDIA graphics, Wi-Fi, Bluetooth, storage and laptop drivers compiled in, and nothing else.

What's in the image

KernelLinux 7.2.6, monolithic, with drivers for almost everything built in (Wi-Fi, Bluetooth, Intel/AMD/open NVIDIA graphics, storage, sound, laptop hardware, exFAT/NTFS/btrfs/XFS); no firmware bundled
Initsystemd 261, with journald, udevd and logind; the base services are plain units in /etc/systemd/system/
Servicessystemd and NetworkManager only. No bundled desktop or extra daemons
UserlandGNU bash 5.3 as /bin/sh, GNU coreutils, tar, sed and gawk on glibc
Softwareget: build a source tarball and install it
InstallerNo GUI. The handbook has every command, and systemlinux-install is a terminal script that runs the same steps: whole disk or an existing partition, with optional LUKS encryption
BootGRUB 2.12, UEFI x86_64 only. Live entries: normal, copy to RAM, debug shell
MemoryAbout 3 GB; the “copy to RAM” entry needs the whole 1.9 GB image in memory on top
